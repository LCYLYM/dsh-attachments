交付的关键流程

操作实际行为
文件夹 → 对话目录预检、排除项说明、单张文件夹卡片。先暂存，发送序列化时才上传到对话工作目录。
文件夹 → 左侧栏明确显示“导入副本”，确认后复制到主机管理的导入目录，再调用工作区注册接口。测试注册表不是实际 DSH。
使用主机原目录显式提供运行 DSH 的主机绝对路径，只注册，不上传、不复制；不凭同名文件夹猜路径。
预览 / 记录栅格图片与有界文本预览，其余格式下载；已保存批次可查看和再次附加。没有替换原生历史气泡。
失败 / 重试两路原始字节传输、校验、取消，重试跳过同一批次已完成文件。不是字节级断点续传。

先运行，再判断体验

解压源码 ZIP，进入 better-attach。演示只需 Node.js 22.16+；装入 DSH 还必须满足它自身的 Node 版本要求。演示不接模型，文件会真实写入系统临时目录。

npm run check
npm run demo

# 浏览器打开：http://127.0.0.1:4173
# Windows：START-DEMO.cmd
# macOS / Linux：sh START-DEMO.sh

先点“试用示例文件夹”，检查排除项和草稿；再点“试用图片与文件”预览。拖动一个测试文件夹到侧栏，确认副本的落点。使用“附件记录”检查已保存批次。终端 Ctrl+C 停止服务。

预览不等于模型已经看到了图

纯图片拖放留给官方链路；混合文件中的图片可以预览，但属于路径附件。文本最多展示前 128 KiB；HTML、SVG 不作为可执行页面加载。PDF、Office 等没有假装内置解析器。

带回你的仓库

保留 npm 名称 dsh-multimedia-webui-input。源码 ZIP 不含伪造 Git 历史；覆盖工具保留原 .git 和未包含文件，写入前创建相邻备份。先在自己的检出目录创建候选分支，审阅差异，再测试。

node scripts/overlay.mjs /path/to/your/dsh-attachments
node scripts/overlay.mjs /path/to/your/dsh-attachments --apply

# 候选包的本地 DSH 安装，仅在独立测试环境执行：
dsh plugin --profile web add /absolute/path/to/better-attach
dsh --profile web --dump-config
dsh --profile web

卸载命令是 dsh plugin --profile web remove dsh-multimedia-webui-input。不同时加载旧版和其他接管普通文件拖放的插件。安装、卸载和真实发送必须在实际环境验证；不能用演示成功替代。

调研结论与市场

官方当前主干已包括普通文件上传和卡片；WJZ-P、CocoSgt 和 djt889 都存在不同附件或路径引用方案。因此定位不是“第一次支持文件”，而是 对话与侧栏各司其职，副本和原目录清楚，失败状态可恢复。详细比较在 docs/RESEARCH.md，取舍在 docs/DECISIONS.md。

dsh.pub 按公共仓库提交、解析默认分支提交并做收录契约检查；dsh-plugin.org 提供 Topic 发现与收录说明。仓库需要真正设置 dsh-plugin Topic，不是只在 README 写井号。两者都不能替代你的运行验证。本次没有提交，也没有加伪造的已收录徽章。

当前必须知道的限制

HTTP API 只接受回环访问，不支持远程或公开反向代理部署；未发送 File 刷新后需重新选择；不迁移旧版附件；不做完整 gitignore 或内容秘密扫描；未实测最大文件数和体积；已提交附件不会自动删除。旧原文件和导入工作区不被会话附件清理操作删除。

发布前门禁

npm pack 可以生成本地候选包；npm publish 会经过 prepublishOnly，缺少真实 DSH 证据时有意失败。本次确实运行过该检查，并记录了缺少证据的失败原因。完成实机测试后再填写真实版本、候选 commit 和去敏证据，不使用虚构的勾选放行。
